# ADR-0006：钥匙新鲜度要结构化判断，文本只当兜底

- 状态：**设计（未落地）** —— 记下来，避免以后又把「靠文本」当成主手段
- 相关：ADR-0005

## 背景

ADR-0005 让「出站失败」能自愈，但它依赖对端回的那句文本。而这个判据在**协议层是唯一**的：
原版 IPMsg 的解密失败回执就是一条普通 `IPMSG_SENDMSG`。真正的问题是「我方缓存的钥匙是否还新」
**没有可验证的判据**，只能等出错。

## 决定（待实施，按价值排序）

1. **入站解密/验签失败即视为轮换**：对端换钥匙后它发来的消息，我方用旧钥匙验签必然失败。
   这是**结构化**信号（`peer_pubkeys()` 的候选全部不命中），可据此撤缓存 + 重取，
   与 ADR-0005 对称，把「两枚硬币的另一面」补上。
2. **发送前校验指纹**：我方已有 `fingerprint()`（设置页核对用）。发送前若发现
   缓存指纹与最近一次公告/应答不一致 → 先重取再发。
3. **定期确认**：把 `GETPUBKEY` 挂到已有的周期性 announce 扫描上（N 分钟一次、每对端一个
   小包），让「缓存是否还新」变成**周期性验证**，而不是靠运气。
4. 文本判据（ADR-0005）**保留为兜底**，不作为主手段。

## 后果

- 出站「每条都发不出去」这类故障，在 3 落地后会**在第一次发送前**就被发现（而不是靠对端抱怨）。
- 代价：周期性多几个 UDP 小包；需要设计节流，避免与 `PLAIN_PROBE_BUDGET` 的语义纠缠
  （那条线判「对端能力」，这条判「我方缓存新鲜度」，实现时必须分开计数 —— 与 ADR-0005 里
  「重试不计入探测预算」同一条原则）。
