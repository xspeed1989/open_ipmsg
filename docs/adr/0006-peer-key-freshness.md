# ADR-0006：钥匙新鲜度要结构化判断，文本只当兜底

- 状态：**已落地**（检查 3；检查 1 原已存在；检查 2 由检查 3 覆盖）
- 相关：ADR-0005

## 背景

ADR-0005 让「出站失败」能自愈，但它依赖对端回的那句文本。而这个判据在**协议层是唯一**的：
原版 IPMsg 的解密失败回执就是一条普通 `IPMSG_SENDMSG`。真正的问题是「我方缓存的钥匙是否还新」
**没有可验证的判据**，只能等出错。

## 落地情况## 落地情况

1. **入站验签失败即视为轮换 —— 原已存在**：EncIPDict 的候选公钥循环全部不命中时，
   会走 `crypto_rehandshake(ctx, from, key, "encipdict-key-mismatch")`（`GETPUBKEY` + 主动推
   `ANSPUBKEY`，由 `try_rehandshake_gate` 按 10s/IP 限频）。这条与 ADR-0005 对称，**不必重写**。
2. **发送前校验指纹 —— 由第 3 条覆盖**：发送路径没有单一收口（多处 `peer_pubkey()`），
   而扫描间隔是 2s —— 阈值一到，最多 2s 内就会补一次确认，效果等价于「发送前后校验」，
   却不必在每个发送点插桩。**尤其是进程刚起来、缓存来自磁盘的那一刻**（`peer_key_age_secs() == None`）
   算作「从未确认」→ 立刻确认。
3. **周期性确认 —— 已落地**：与预握手**合并成一次扫描**（见下），对已有缓存公钥、声明加密、
   未被标成明文的对端，钥匙「太久没确认」（`KEY_REFRESH_INTERVAL_SECS = 300s`）或「从未确认」
   时补发一条 `GETPUBKEY` 重新确认。
4. **预握手「用到上限就停」改成慢节奏 —— 已落地**（合并时一并做掉）：`HANDSHAKE_RETRY_MAX = 5` 次
   快节奏（2s）之后不再彻底停下，而是降到 `PEER_KEY_SLOW_RETRY_SECS = 60s` 继续 ——
   丢掉的是频率，不是这件事本身。原来「用完就等对端下一轮 45s 宣告」，代价是首条消息明文发出。
5. 文本判据（ADR-0005）**保留为兜底**，仍不作为主手段。

### 合并（原来两遍独立扫描）

`handshake_sweep` 一次扫描处理两件事；判据收在**纯函数** `key_ping_plan(has_key, retries, age)`
一处（返回 `Fast` / `Slow` / None），限频收在**一张表**（`key_ping_at`，
`allow_key_ping_at(key, gap)`），发送收在**一个函数**（`send_getpubkey_ping`，`note` 只进日志）。
合并前的两遍扫描、两套限频、两份判据都删了。快节奏也记一次补发时刻（gap = 0 = 不看墙钟），
所以「快节奏用满后的第一发慢节奏」会等满 60s，而不是紧接着再来一发。

**仍然分开、且必须分开的**：`probe_counts`（`PLAIN_PROBE_BUDGET`）。它判的是**对端能力** ——
攒够就把对端标成明文；而重试次数与新鲜度判的是**我方这一侧**（链路丢包、缓存是否过期）。
两者混在一起，2s×3 的丢包就能把支持加密的对端误标成明文。所以补发一律走**不计探测预算**的
`send_getpubkey_ping`。

## 后果

- 「对端换了钥匙、而它的上线宣告在 LAN 上丢了」这类故障（ADR-0005 的前置条件）现在会在
  **≤300s + 2s** 内自己发现并修好，不再依赖对端抱怨。
- 代价：每对端 5 分钟一个 UDP 小包（对端回一条 `ANSPUBKEY`，顺手把新鲜度刷新）；
  预握手在快节奏用满后是每 60s 一个 —— 对端一直不回应也不会被刷爆。
- `key_ping_plan` 是纯函数，快/慢/确认三种情形都有单测覆盖，改节奏不必起网络。
