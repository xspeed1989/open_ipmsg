# 接收端按内容去重：同一份内容只留一个文件

接收文件时落盘只有一处命名逻辑（`unique_path`：`name(1).ext`、`name(2).ext`…），没有任何内容级
判据 —— 同一个人把同一张图、同一个表情、同一份文档发两次，下载目录里就多一份；重发、断点重传、
`adopt_completed_download` 那条抢救路径也一样。长期下来目录越来越大，而这些副本的字节完全相同。
**决定：按内容哈希（SHA-256）去重，命中则硬链接到公告名，不支持硬链接的文件系统回落到复用已有
路径。** 判据与 emoji 模块已有的「同内容即同一张表情」一致（`content_sha`）。

## 决定

- **判据是内容哈希**，不是名称/大小：同内容不同名（`剪贴板图片.png` 与 `剪贴板图片(1).png`、
  同一张图从不同工具粘出来）必须判成同一个；而名称+大小会把「同名不同内容」误判成重复 —— 那是
  丢文件，比多占空间严重得多。
- **覆盖所有接收的附件**（含文档、压缩包），不只图片类：它们走同一条落盘路径，只按类型分治会
  多一个分支、多一处将来会漏的地方。
- **索引落盘**（`<data_dir>/received_files.json`，原子写：临时文件 + rename），内容是
  `sha256 → { path, size, name, ts }`。放在数据目录而不是下载目录：换下载目录、用户在文件管理器
  里翻动文件，索引都不跟着被搬来搬去。
- **命中时**：优先 `hard_link` 到 `unique_path(dir/safe_name)` —— 同 inode、不额外占空间，且磁盘上
  的名字与消息里显示的一致。硬链接失败（FAT32/exFAT 的 U 盘、跨卷、权限）时**回落到复用已有路径**：
  记录里的 `path` 指向那份老文件，临时文件删掉，功能不丢。
- **落点**：接收侧唯一的收尾动作抽成 `settle_download(dir, tmp, safe_name, index) -> PathBuf`，
  正常下载与 `adopt_completed_download` 两条路径都走它（否则抢救路径继续造副本）。索引住在
  `mod transfer`（它就是文件传输这件事的状态），沿用该组的接口纪律。

## 落盘索引的失效处理（选它就要付这份代价）

索引是**可以随时丢掉重建的缓存**，不是真相来源。三条规矩：

1. **命中时校验**：`path` 不存在、或大小与记录不符 → 丢掉这条、当作未命中（不做「猜它去哪了」）。
2. **写入失败不阻断**：索引写失败只记诊断，下载结果照常交付（用户拿到文件比索引完整重要）。
3. **有界**：条目数超过上限（暂定 4096）时按 `ts` 淘汰最旧的；路径已失效的条目在淘汰时一并清掉。

**不做**的事：不自动删除已经在下载目录里堆起来的旧副本 —— 自动删用户文件的风险高于收益。
要清理的话另做一个**手动入口**（按内容哈希找重复、保留一份、删前必须让用户确认）。

## 落地记录（2026-10-12）

已实现：`mod transfer` 的内容索引（`received_files.json`，原子写、4096 上限、命中校验、
写失败不阻断）+ `settle_download()`（流式 SHA-256 → 硬链接到公告名 / 不支持则复用 / 未命中照旧
落盘并记索引）+ adopt 抢救路径的「落地后补一步去重」。单元用例
`settle_download_dedups_by_content` 钉住四条：同内容共享同一 inode、不同内容各留一份、
索引失效当未命中、索引确实落盘。

**与上面测试计划的偏差**：计划里的「自检加一条『同一文件发两次、下载目录只多一个』的端到端断言」
本次没加（落盘判重已由单元用例在正确的 seam 上钉住，自检只间接覆盖接线）。

## 后果

- 同一份内容在多条消息里会共享同一个文件（或同一 inode 的多个名字）：改其中一个名字下的内容会
  影响另一条记录（硬链接是同一份数据）。这是 Content-addressed 的应有之义，但要在
  「打开所在文件夹」之外**不要**提供「编辑」入口 —— 现在也没有。
- 大文件不能整份读进内存算哈希：哈希要**流式**从临时文件读（复用 SHA-256 口径，不用
  `content_sha(&bytes)` 那个整块接口）。
- 下载目录里已有重名文件时，`unique_path` 仍负责避免覆盖 —— 去重发生在它的**之前**（先判内容，
  命中就不必新建名字了）。
- 测试：一个纯/半纯的 `settle_download` 用例（临时目录里造两份同内容、断言磁盘上只多一个文件且
  两条记录指向同一份）+ 自检里加一条「同一文件发两次，下载目录只多一个」的端到端断言。
