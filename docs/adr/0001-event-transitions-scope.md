# 事件迁移只覆盖后端事件驱动的那半边

`src/store.js` 的状态改动分三类：后端事件驱动的十一个订阅、用户动作、启动加载。本次只把「事件驱动」那半边抽成事件迁移 module，用户动作与启动/加载继续留在 store —— 缺陷高发区集中在事件侧（图片卡在「下载中」、监听就绪前的未读补数、已送达状态三处修复都在这里），而把用户动作一起收进去会让新 interface 横扫十一个组件。代价是状态机只被抽出了一半，看上去可疑：**这是有意的**，全量收敛留给以后单独做。

## Considered Options

- **全量收敛**：连用户动作一起收进 module，store 只剩状态容器与 IPC 接线。收益最大，但新 interface 要同时覆盖事件与动作两条轴，改动面横扫全部组件，而当时还没有 characterization 网兜住。
- **只抽抽出过事的那几条事件**：`msg-in` / `file-progress` / `msg-delivered` / `msg-read`。改动最小，但剩下七条订阅继续裸奔，下一轮缺陷还会长在同一个地方。

## Consequences

- 事件迁移 module 只被 store 调用；组件不从它取任何东西。
- 用户动作触发的状态写入仍留在 store，所以「谁改了 `chats`」这类问题在本次改动后仍有两处答案 —— 这是本决定接受的代价。
