# ADR-0007：换钥恢复与发件箱投递预算

状态：已落地。补充 ADR-0005 / ADR-0006。

## 问题

撤销过期公钥只解决了取钥问题，没有锁住消息的加密要求。下一次重发可能在新钥尚未返回时走明文。
在线重发超限后未出队，离线补投也没有投递次数，导致错误自动回复与待发消息不断循环。
重复的 DecryptErr 在入站去重前处理，还会再次撤销刚取回的新公钥。

## 决定

- 已密封消息记录 `require_encryption`，在线转离线及重启后保留；等待换钥、关闭加密或密封失败时均不能降级明文。
- 收到 DecryptErr，为该会话尚未确认的消息锁住加密要求并取新钥；入站持久化和去重之后才执行，旧回复重传不能撤销新钥。
- 换钥期间的新消息明确报错，保留由用户重发的选择。取得公钥后重发沿用原包号，重新密封；不自动生成新包号。
- 在线和离线消息共用每条最多 5 次投递尝试的预算（首投 + 4 次重发），投递前原子占用次数及间隔。在线转离线不重置预算。
- 离线预算、最近投递时刻和加密要求落盘；预算无法落盘时不投递。超限记录保留，只有真实 RECVMSG 才标记送达。
- 离线附件保留原文件 ID、元数据及属性，重投只重登记槽位，保证同包号的公告身份稳定。
- 旧版队列缺少已尝试次数，升级时保留记录并暂停自动补投，避免重新播放积压消息；用户确认后可手动重发。

## 验证

回环 UDP 回归覆盖旧钥首投、DecryptErr、等待换钥、重复错误回复、新钥重新密封、真实送达确认，
以及离线附件在换钥和重启前后的公告一致性。状态测试覆盖预算、间隔、在线转离线、持久化恢复和旧队列暂停。
密封失败与重发超限均验证没有明文降级或虚假送达。
